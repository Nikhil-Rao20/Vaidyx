# Brief Q2: UI review against the real backend, every role, desktop and mobile

Goal: the new interface at http://127.0.0.1:7000/tb-nik must work for real, for every role, on a laptop and on a phone, and look clean, simple and organised for busy doctors. Run the Playwright specs in real mode, add real-mode journeys, look at every screenshot yourself (Read tool on the PNGs), fix what is broken or ugly, rebuild, repeat.

Project: web/tb-nik (`export PATH=/data/vaidyx/tools/node/current/bin:$PATH`; build `npx vite build` writes static/tb-nik, which the running app serves at once; no app restart needed for frontend changes). Playwright: `LD_LIBRARY_PATH=/data/vaidyx/venv/pdf/lib npx playwright test -c e2e/playwright.config.ts` (real mode: env TBNIK_USER, TBNIK_PASSWORD, TBNIK_ROLE; mock mode: TBNIK_MOCK=1). Demo logins: ~/vaidyx/.tb_v2_demo_logins (tab separated: username, password, ...; read in the spec runner from the file, never print or commit a password): tb-breast-doc (treating), tb-mdt (coordinator), tb-rad-doc (supporting), tb-path-head (supporting head), tb-breast-admin (department admin), tb-root (root admin). Every demo account starts with setup_needed (the welcome stepper): the journeys complete it once per account (that is fine, it is the intended first-login flow).

1. Real-mode journeys (new spec e2e/shots/real.spec.ts) per role: sign in, welcome (first time), home, open a Case File (TB-DEMO-P19, TB-DEMO-P18A, TB-001), every panel (helpers, team, board form, published, source viewer), the reports list and timeline, the Ask box (one question at most per run: model calls are slow), New Case File up to the last step without creating (unless the brief of Q1 created one already), meetings list and agenda, the room screen of a meeting (create one as tb-mdt named "UI review" if none exists), the member view, join by code, settings, activity, admin set-up (tb-root), people (tb-breast-admin), the supporting doctor's request cards (tb-rad-doc). Desktop 1366x768 and 1920x1080, mobile 390x844 (Dock nav visible and usable), light and dark for the main pages. Save to docs/ui/build/shots/real-<role>-<page>-<state>-<theme>-<width>.png.
2. Look at every shot. Fix: layout breaks, overflow, unreadable contrast, crowded screens, jargon (never "Level 1 / 2", "tier", "accession chip"), missing states (loading, empty, error), buttons without states, anything a busy doctor would not find, any console error, any request that fails (4xx/5xx in the network log that the page did not plan for). Keep the existing theme. Keep it simple.
3. Failures: run the mock-mode suite too (`TBNIK_MOCK=1`), keep it green.
4. Accessibility: run axe-core (`npm i -D @axe-core/playwright`) on the main pages in real mode and fix serious and critical issues.
5. Write docs/ui/build/shots/INDEX.md: a table of every page and state with the screenshot file names, grouped by role, and a short list of what you fixed.

Your files: web/tb-nik/** only (and static/tb-nik through the build). Do not touch backend files; if a backend bug blocks a page, describe it precisely in the report (route, request, response). Another builder (Q1) is running the end-to-end scenario and fixing backend bugs at the same time; it may restart :7000 (wait and retry when the app is briefly down).
