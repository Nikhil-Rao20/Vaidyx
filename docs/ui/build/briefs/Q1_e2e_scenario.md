Goal: prove the whole loop works on the running services, the way the owner will demo it, and fix every bug you find on the way. Write tumour_board/eval/e2e_nik.py (runnable again: `python -m tumour_board.eval.e2e_nik [--keep]`), run it, fix, run again until every step passes, and leave a log at docs/ui/build/E2E_RESULT.md (step, result, evidence; no secrets).

Services (all running, localhost): Vaidyx :7000 (restart it with `scripts/demo_services.sh restart app` after backend changes; it takes up to 3 minutes; wait for /api/health), demo HIMS :7130 (logins in data/his_mock/logins.tsv; JSON APIs under /his/api and /desk/api take `Authorization: Bearer <data/his_mock/token>`; screens need the login cookie and a CSRF field), Orthanc :8042, LiveKit :7880, models :8100 and :8101 (real model calls are fine here but slow: summary about 30 s, brief about 15 s; keep the number of model calls small). Vaidyx demo logins: ~/vaidyx/.tb_v2_demo_logins (tab separated: username, password, ...; never print passwords): tb-breast-doc (Breast Surgery consultant), tb-mdt (coordinator), tb-rad-doc and tb-rad-admin (Radiology), tb-path-head (Pathology head), tb-medonc-doc, tb-root (root admin). Create a resident account for the scenario through the new accounts API as the Breast Surgery department admin (tb-breast-admin) with an email login, and use the mailto password from the response (in memory only) to sign in, then change it (forced change).

Scenario (SPEC.md section 8), each step checked through the API and recorded:
1. HIMS: register a new synthetic patient (name ending "(SYNTHETIC)", woman, 58) through the JSON API; OPD visit in Breast Surgery; OPD note; orders: mammogram, core biopsy (hpe_biopsy), CBC, LFT, and a CT chest; lab: collect, results, sign (lab doctor); radiology: schedule today, report, sign the mammogram (public image from the library if the PACS import mapped one, else synthetic); pathology: receive, HPE final signed; IHC ordered but left pending; CT chest left not done (so it shows "not found in the file").
2. PACS: the mammogram study is in Orthanc (QIDO by accession and PatientID = UHID).
3. Vaidyx: Dr Breast (tb-breast-doc) creates the Case File from the UHID (POST /cases/from-his, protocol breast, setting as recorded), waits for the fetch job; GET /cases/{id}/slots shows values with quotes (mammogram, HPE), IHC "waiting" or "not found", CT chest "not found"; sets urgency 4; makes a join code; the resident joins with /case-join; the resident proposes "not needed" on one line; the consultant approves (the waive runs as the consultant); the consultant asks Pathology for the IHC via the slot's ask-department; Pathology (tb-path-head) sees the request in GET /inbox and acknowledges it.
4. HIMS: the pathologist enters and signs the IHC; Vaidyx re-fetch (POST /cases/{id}/his/refetch) brings it; the request closes by itself; the slot is now found.
5. Ask: one question through POST /cases/{id}/chats (real model; check citations are verbatim quotes of the reports), shared with the team (the resident sees it).
6. Ready: board question typed (slot value), Mark ready (POST /cases/{id}/ready); the ready hook prepares the summary and the five briefs (wait for them or check they are queued; at least the summary must arrive within 3 minutes).
7. Meeting: the coordinator creates a meeting today with video, puts the Case File in For discussion, sends the agenda, makes a code; two members join with the code (one admitted as in the room, one remote); WebSocket connection for the room screen (cookie auth) receives state; the coordinator sets the current case, opens the images on the shared screen (the viewer url arrives on the socket and GET of that url through /api/tb/pacs answers 200 for an admitted member), a member types a question, the decision text is typed live (decision_live broadcast), saved after read-back (POST decision, outcome decision), end case (cards requested), a head gives a card; LiveKit: POST video-token, and the token validates against http://127.0.0.1:7880/rtc/validate.
8. Outcome: the owner gets the outcome notification; GET /case-list shows the Case File as decided.
9. Owner rule 5: upload the demo documents of one demo patient (data/his_mock/documents/p19-*.pdf, the synthetic PDFs) as outside reports into a second fresh Case File for that patient and check they are read and filed (POST /cases/{id}/documents, wait for the job, documents listed with types).

Fix bugs where they are (tumour_board/**, routes/tumour_board_routes.py, his_mock/**), with tests for each fix; run `TB_SCHEDULER=0 /data/vaidyx/venv/app/bin/python -m pytest tumour_board/tests -q` and `/data/vaidyx/venv/app/bin/python -m pytest his_mock/tests -q` after your fixes.
