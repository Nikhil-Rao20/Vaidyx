# Brief F1: shell, sign-in, home, new Case File, requests, settings, admin (frontend)

Project: web/tb-nik (React 18 + TypeScript + Vite 8 + Tailwind 4 + shadcn/ui + Motion). Build output goes to static/tb-nik (served at /tb-nik by the app on :7000).

Your folders: src/app/* (AppShell, guards, PageSkeleton, NotFound, ErrorPage), src/features/auth, home, newcase, requests, settings, admin (each with routes.tsx exporting authRoutes, homeRoutes (includes /home, /cases/new, ...), requestRoutes, settingsRoutes, adminRoutes), src/components/* (shared components; NOT src/components/ui), src/lib/* additions (format.ts, filters.ts, notifications.ts, push.ts, cancers.ts, nav.ts, types.ts), src/hooks/*, public/sw.js, e2e/playwright.config.ts and e2e/shots/{shell,auth,home,newcase,requests,settings,admin}.spec.ts. Do NOT touch src/features/casefile, src/features/meetings, src/lib/live.ts, src/lib/video.ts (another builder), src/App.tsx, src/lib/api.ts, src/lib/session.tsx, src/lib/appearance.ts, components.json, vite.config.ts, src/components/ui/* (shadcn: button card dialog dropdown-menu tooltip popover select tabs switch checkbox label separator scroll-area avatar progress radio-group toggle collapsible accordion badge input textarea sheet skeleton table command sonner alert). src/index.css: only small additions at the end.

API: SPEC-API.md (me.py, cases_list.py with path /case-list, team.py with /case-join, /waiting and proposals, setup.py, push.py) plus existing endpoints in docs/ui/build/maps/backend_map.md (GET /cases, /home, /org, /inbox, /notifications, POST /notifications/read, /referrals, requests routes, GET /his/lookup, POST /cases/from-his, GET /protocols, GET /protocols/{pid}, GET /jobs/{id}). The backend is being finished in parallel: code against the contract; a 404 shows an honest "not available yet" state; never crash.

Component libraries allowed (owner's list; restraint on clinical screens): React Bits (Dock, Stepper, GooeyNav, ClickSpark, FuzzyText, ScrollFloat, Counter, BorderGlow, ElasticSlider), Magic UI (animated-theme-toggler, ripple-button, interactive-hover-button, shine-border, scroll-progress), Kokonut UI (profile-dropdown, action-search-bar, smooth-drawer, avatar-picker, hold-button). Several are already vendored in src/components/vendor. Dock = mobile nav; Stepper = first-login profile set-up and admin guided set-up; FuzzyText = error page.

Build, each page complete with loading, empty and error states:
1. AppShell (exists, check and finish): slim top bar on >= 1024 px (wordmark, 3 to 5 items per role from me.primary_role and roles, union for multi-role: treating/resident Home, Case Files, Meetings; supporting Home (requests), Meetings; coordinator Home, Case Files, Meetings; dept admin + People; root admin + Admin; auditor Activity), action search (UHID / name / IP / OP No. from GET /case-list; commands New Case File, Join a Case File with a code, Join a meeting with a code), bell (GET /notifications popover, mark read), profile dropdown (name, roles, theme toggle, text size, Settings, Activity, Sign out). Mobile: top bar + Dock. Toasts with aria-live. 401 -> /sign-in with from.
2. Auth: /sign-in (email + password, TOTP step when requires_totp, inline errors, rate-limit message, "Forgot password? Ask your department admin to reset it"), /first-login (forced change: current, new, confirm, strength hint), /welcome (4-step stepper: name, title, registration number for doctors, photo; theme and text size seen live; start page and mobile number with the visibility switch; done screen with the gift: type one UHID to start a Case File). PUT /me/profile, POST /me/password.
3. Home (treating, resident, coordinator): GET /case-list newest first; search; filter chips (date range, patient name, treated by, organ/cancer, imaging present, urgency, status, board date, mine only); saved filters from profile.saved_filters; rows: urgency tag 1..5 (colour only on 4 and 5, plus icon), patient line, cancer, "from Dr X, Dept Y", status word with icon, board date, last change; row lifts with an arrow on hover; click opens /cases/:id; "+ New Case File"; "Waiting for me" strip from GET /waiting with Approve / Return for consultants; residents see "waiting for Dr X"; coordinator gets a Next meeting card (GET /meetings) and the ready list; empty state with illustration; first-login gift box when there are no Case Files.
4. Supporting home (primary_role supporting) and /requests: request cards (patient, UHID, IP/OP, accession, what is missing, who asked, due date, Open in RIS / PACS (http://127.0.0.1:7130/his?q=<accession> and the viewer url when available), Acknowledge, Done with a note); tabs Open / Done. Data: GET /inbox plus GET /cases (REQUESTS-scope cases) and GET /cases/{id} limited view requests.
5. New Case File /cases/new (3-step stepper): patient lookup (GET /his/lookup?identifier=; registrations; similar registrations "link, never merge"; existing Case File for the same patient via GET /case-list with open or join); cancer picker (GET /protocols for built checklists incl. cup; top 10 per group in src/lib/cancers.ts from NCRP 2020 with the source noted: men lung, mouth, prostate, tongue, stomach, oesophagus, colorectal, liver, larynx, NHL; women breast, cervix, ovary, corpus uteri, lung, mouth, colorectal, gallbladder, thyroid, oesophagus; children leukaemia, lymphoma, brain, bone, kidney, retinoblastoma, soft tissue, germ cell, liver; a cancer without a checklist shows "no checklist yet: the generic rule applies"; CUP maps to protocol cup); NCG setting "as recorded" from GET /protocols/{pid}; hospital level read-only; logistics pre-filled (fetch window 12 months, board question, urgency 1..5 required with no default, presenter self, consent switch) -> POST /cases/from-his then PUT /cases/{id}/urgency; fetch progress via GET /jobs/{id} with live steps; then /cases/:id.
6. Settings /settings: profile, appearance (theme, text size, start page), saved filters, notifications (PUT /me/notifications; browser push via GET /push/key + POST /push/subscribe; public/sw.js shows the notification), security (change password, TOTP status), /activity (GET /me/activity; coordinator / auditor see GET /activity with filters).
7. Admin /admin (root admin): guided set-up stepper (GET /setup; hospital; departments tick list with email + phone; people invite rows with a "Send login by email" mailto button per created person; hospital system URL + Test (POST /his/test); board: coordinators, five heads, meeting defaults); /people for department admins (GET/POST/PUT/DELETE /org/departments/{dept}/doctors + reset password mailto).
8. Error page (FuzzyText 404 / 500), offline banner.
9. Playwright: e2e/playwright.config.ts (baseURL http://127.0.0.1:7000, headless chromium; if browsers are missing run `npx playwright install chromium`); specs log in through POST /api/auth/login using env TBNIK_USER and TBNIK_PASSWORD (never hard-coded), visit each page at 1366x768, 1920x1080, 390x844, light and dark, save to docs/ui/build/shots/<page>-<state>-<width>.png; failure states via page.route (500, empty lists).

Quality: `npx tsc -b --noEmit` and `npx vite build` pass with no errors at the end; lazy-load pages; API types in src/lib/types.ts; no console errors.
