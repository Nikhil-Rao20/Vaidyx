# Vaidyx-TB build spec: demo HIMS, demo PACS, new website (/tb-nik)

Written 18 Oct 2026 from the interview answers (docs/ui/questions, 281 questions, Settled and Check sheets) and the owner's build rules. This file plus RUNLOG.md drive the whole run. Where answers collide, the rule is: take the best case for real Indian hospital life (busy, hectic schedules) and keep building.

## 0. Rules that never bend
- Scope: Vaidyx checks, routes, summarises, flags. Never diagnosis, staging, image reading, treatment advice, clinical urgency judgement. Every fact shown carries a verified verbatim quote. Clinician confirmations beat model output. Everything audited.
- Terminology: Tumour Board Case File, Responsible Department, Pre-Authorization, Points for review, Human oversight (expert over the loop). No em or en dashes in UI, reports, code comments or docs. Model labels: Qwen3.5-4B (Chinese, non-medical), Gemma-4-31B (non-medical), on the model page and in exports.
- Commits: per finished piece, short message, author Nikhil-Rao20 (git -c), never push, never Claude. Never commit data/, docs_Eswar/, CLAUDE.md, .claude/.
- Never touch the real case data/tumour_board/cases/TB-2026-bharath. Never print passwords. Only synthetic data in HIMS; PACS images from CC BY public datasets relabelled with fake IDs.
- Old /tb stays as it is. New site at /tb-nik, same backend. Laptop first; mobile works (Dock nav). Text only (no speech). Localhost only; security built in for later sharing.

## 2. Roles (Vaidyx)
Treating doctor (consultant, owner of Case Files), Resident / PG / fellow (member of a Case File team, cannot sign; proposes, consultant approves), Supporting doctor (Radiology, Pathology, Microbiology, Biochemistry, Nuclear Medicine, Clinical Pharmacology; sees requests only), MDT Coordinator (runs meetings, records decisions, chairs; no clinical resolution unless a doctor), Department admin (accounts, contacts, leave), Root admin (hospital set-up; non-clinical), Auditor (read-only activity), Outside expert (meeting shared screen only; identity by consent), Vaidyx admin (break-glass with reason, owner told; no clinical actions). One login can hold several roles (root admin stays non-clinical). Departments: 23 treating + 6 supporting (settled list; Medical Genetics and GI Surgery endoscopy also receive requests).

## 3. The new website: screens and behaviour
Design system (from static/tb/tb.css, kept): primary #00c0b5, primary-hover #00ada3, on-primary #0b1f24, accent #009c94, link #046483, indigo #3e5cad; tints #e6f3f7 / #f2f9fb / line #b6dde4; ink #1f2933, body #3e4c59, muted #52606d, line #d9e2ec / #c5d1dc, bg #f5f7fa, panel #fff; status ok #1e6b45 on #e5f4ec, warn #8a5300 on #fdf1d8, bad #b23a2f on #fbe9e6, review (violet) #5b3fc4 on #efebff; radius 10px; shadow layered (outer lighter, inner stronger); fonts Atkinson Hyperlegible + JetBrains Mono (self-hosted, OFL). Dark theme: same hues on dark surfaces, every status colour re-checked for 4.5:1. Spacing on a 4 px grid; body 16 px; roomy rows (48 px). Status = colour + icon + word, never colour alone. Buttons: icon + word for clinical actions; icon only for copy, close, search, print. Every control has default, hover, pressed, disabled, loading states. Micro-interactions: button turns into "Sent" with a tick + 2 s slider (screen-reader announced) + Undo (10 s) where undoable. Errors and empty states: small illustration + one plain sentence with the cause + one action, in place; details folded. AI waits: preview filling in (grey lines become sentences only after their quote is verified). Hints: things look clickable; rows lift and show an arrow on hover; one-line tooltips; no help paragraphs. Mobile: Dock nav (React Bits), same pages responsive.

Allowed component libraries (owner's list): React Bits (dock, stepper, gooey-nav, click-spark, fuzzy-text, scroll-float, magnet-lines, masonry, lanyard, chroma-grid, border-glow, elastic-slider, counter, drift-wall, scroll-expand, logo-loop, cursor-grid), Magic UI (animated-theme-toggler, ripple-button, interactive-hover-button, shine-border, scroll-progress, dotted-map, glyph-matrix), Kokonut UI (profile-dropdown, action-search-bar, smooth-drawer, avatar-picker, hold-button, card-flip). Use with restraint on clinical screens; effects never slow the doctor.

### 3.1 Shell
Slim top bar (desktop): logo, 3 to 5 items per role (Home, Case Files, Meetings, Requests for supporting, Admin for admins), action search bar in the middle (UHID, name, IP/OP No., commands), bell with count, profile dropdown (name, roles, theme toggle, text size, settings, activity, sign out). Multi-role: union of items. Mobile: Dock at the bottom with the same items. Start page per profile (Home, last Case File, Meetings).

### 3.2 Sign in and first login
Email + password (admin-created, random, sent by mailto from the admin's own mail). First login: must change password; then profile set-up (stepper: name and title, department(s), registration number for doctors, photo via avatar picker, theme and text size seen live, start page, mobile number with consent to show it to signed-in hospital members). TOTP optional (existing core support) and required for coordinator, admins, remote logins (flagged in settings, enforced later with deployment). Rate limits on login (5 tries then 15 min). Session cookie httponly + samesite; TB idle timeout.

### 3.3 Home (treating doctor)
One neat list of the department's Case Files, newest first; search box; filters as chips (date, patient name, treated by, organ/cancer, imaging present, urgency, status, board date, mine only); saved filters ("pin what my home shows"). Each row: urgency tag [1..5] (5 most urgent; colour only on 4 and 5), patient (name, age/sex, UHID), cancer, owner and tag "from Dr X, Dept Y", status word + icon (Needs you / Waiting on <dept> / Ready for the board / Scheduled <date> / Decided / Archived), board date, last change. Click opens the Case File. "+ New Case File" primary button. Empty: illustration + "No Case Files yet" + button. The gift: on first login the doctor can type one UHID and see the records fetched and what is missing in seconds (no profile needed first).
Resident home: the Case Files they are on, with "waiting for Dr X" items. Supporting home: open requests for their department (request cards) + their replies; nothing else. Coordinator home: next meeting card (date, counts, Send agenda), ready Case Files, chase list, past meetings. Admins: people, departments, hospital, HIS test, activity.

### 3.4 New Case File (stepper, 3 steps)
1 Patient: UHID / IP / OP No. / ABHA / name+age+sex search against the HIMS; shows registrations incl. possible duplicates (person links, never merged); existing Case File for the same patient and cancer: show it, offer to join. 2 Cancer: picker filtered by sex and age from the record (one tap shows all), top 10 badges per group (NCRP 2020), grouping men / women / children / general, manual entry for an unlisted cancer (no checklist yet: generic rule), CUP present. NCG setting "as recorded" chosen by the doctor; hospital level from set-up. 3 Logistics (pre-filled as recommendations): fetch window 12 months, board question (required before ready), urgency (no default), presenter (self), residents to add (code generated), consent flags. Create: fetch runs with live steps; the Case File opens.

### 3.5 Case File page: the fill-in summary
Header strip: patient line (name, age/sex, UHID, IP/OP), cancer + setting, owner + department, board date / meeting, urgency tag (set by Dr X, resident can propose), "N left before the board" counter, buttons: Specialty helpers (6), Team (n), Board form, Published cases, Print / Export (.pptx NCG template) after review.
Left (main) column, the summary that is the checklist. Sections in board order: Presenting history and performance status; Pathology (biopsy date, specimen, histology, IHC/markers); Imaging (each study: modality, date, key findings as reported, comparison); Labs and tumour markers; Staging data as recorded (never computed); Prior treatment; Board question. Each line = label, value as a verified verbatim quote with its source chip (document, page) that opens the page with the quote highlighted, or a blank: "[ not found in the file ]" with its actions in place (Ask <department> (drafts the request), Not needed (reason), Enter a value (fixed list: ECOG, menopausal status, weight, height; shows "entered by Dr X, no report")), or "[ waiting on <dept>, asked <date> ]" with Remind, or "[ needs your confirmation ]" (two values disagree, date, type, patient match, final?) with Review (opens the side panel showing both quotes with the factual differences; doctor picks with a reason). Lines live from the first fetch from verified facts (no AI prose); AI-written paragraphs (history narrative) and the 5 briefs come at the ready mark, labelled "AI draft, not reviewed" until reviewed; stale banner when records change ("1 new since you looked", Show).
Right column: Ask this Case File (shared team chat, saved, each answer with quotes + "open page" chips; "View as" stays general; stale stamp "records changed since"); below: Reports (compact, grouped by OP visit / IP admission, Timeline view toggle; status chips final / preliminary / not signed; Open (PDF viewer with highlights) / Open images (OHIF) ; Upload outside report; Re-fetch now).
Action ladder: in-place for small undoable steps (send drafted request, remind, not needed) with Undo 10 s; side panel (420 px at 1366, non-modal) for steps needing evidence (Review, resident draft approval, request edit) with Approve / Edit / Not needed and auto-advance to the next item; modal only for Sign and lock, Archive, Mark ready (read-back of what is still open).
Resident: every consultant-only button becomes "Ask Dr X to sign off" (resident fills everything; consultant gets an alert and approves / returns with a note from their home or the panel).
One click away: Specialty helpers panel (6 cards: Radiology records check, Pathology, Medical Oncology, Surgical Oncology, Radiation Oncology, Nuclear Medicine; pick one: brief (prepared at ready for the 5 heads, on click for Nuclear Medicine), then a chat thread with that helper; all from records and guideline points, never opinions); Team panel (owner, residents with end dates, departments participating, join code with approval, remove); Board form (coordinator fills; read-only for others; 10 fields: outcome (decision / deferred / referred / not discussed / noted), decision text, rationale as discussed, treatment intent as stated by the board, responsible doctor, next step and date, what is awaited and from whom (if deferred), referred to (if referred), members present, concerns (named, own words)); Published cases (doctor-approved search words; results list; doctor adds; shown with authors, journal, year, link, peer-reviewed or not; procedure and conclusion as verbatim verified quotes labelled "Published case, not advice for this patient").
Audit: not on this page; Settings > Activity (own actions) and full log for coordinator / auditor.

### 3.6 Requests and the department inbox
Request card (supporting doctor): patient, UHID, IP/OP, accession, what is missing, who asked, due date, Open in RIS/PACS (deep link to the HIMS desk / OHIF), Acknowledge, Done with a note. Owner side: requests list per Case File with status, Remind, automatic reminders (audited "Vaidyx (automatic)"), auto-close when the re-fetch finds the record final and signed. Referral (hand-over to another department): receiving consultant accepts; old owner stays until then.

### 3.7 Meetings
Meetings list (coordinator creates by hand: date, time, room, video on/off; no cut-off). Agenda page: two lists (For discussion, For noting) in coordinator's order (drag), Not ready folded; row: patient, owner, presenter, board question, gap left, minutes, Remind; Send agenda (message to members; later additions flagged). Join: hospital members by 6-digit code (in-app only; limited attempts; waiting room until the coordinator admits; "I am in the room" for people physically present). Room screen (the room computer, full screen): current case as slides (Summary first, then Key values with sources, Gaps and waivers, Imaging, Pathology, Points for review) with the fill-in summary on the left; right side opens a report or the OHIF viewer (images open from the room itself); timer per case; members online strip; Vaidyx agent tile only when a stand-in for an absent head is active, with true states (Ready, Reading the question, Thinking, Answering); questions typed by members appear on the shared screen with the answer (text). Coordinator control view (own laptop): agenda, Next / Previous, timer, admit, open record / images on the shared screen, decision form, live decision strip (typed text shows live at the bottom of the room screen marked "not saved"; saved after read-back), end case (member cards). Remote member view: follows the shared screen (can step away), Type a question, Raise hand, call icon shows the number. End of meeting: each board head gets a card per case (Agree / Concern + notes; required for heads) readable by coordinator and owner's team; concerns always in the record. Outcomes: decision, deferred (what is awaited, from whom), referred, not discussed (moves to the next meeting), noted. Outcome sent to the owner (and the one-page decision).

### 3.8 Admin
Guided set-up (stepper, 5 steps, saved as you go): Hospital (name, level, PM-JAY, boards), Departments (tick 23 treating + 6 supporting, contacts email + desk phone), People and roles (invite by email: mailto with random password), Hospital system (HIS URL + token test: must pass), Board (coordinator, the 5 heads, meeting defaults). Later: Settings pages per section. Department admin: doctors list, on leave, contacts, residents with end dates. Activity: own actions for everyone; full log for coordinator and auditor.

## 4. Backend additions (tumour_board/, routes/tumour_board_routes.py)
Stores stay JSON files under data/tumour_board/ (single worker, file locks as today). New or changed:
- Case File: urgency {level, set_by, set_at, proposals[]}, team {owner, residents[{user, added_by, end_date}], departments[], join_code{code, expires, approvals[]}}, proposals[] (resident proposals: action, payload, status, decided_by), chats[] (threads: {id, by, question, answer, quotes[], case_signature, pinned, shared=true}), helper_threads{specialty: [...]}, published_cases[], typed_values[], consent {outside_discussion}, summary_slots (per protocol template: slot id, label, section, fact ids, value, quote ref, status), board_record (10 fields), member_cards[].
- Meetings: sessions {id, date, time, room, video, code, status, agenda{discussion[], noting[], not_ready[]}, order, current, timers, attendance[], questions[], decision_live}, WebSocket channel /api/tb/meetings/{id}/ws (JSON events: current_case, slide, open_record, open_images, timer, decision_live, question, raise_hand, presence, admit, end_case) with per-user auth and role checks; LiveKit token route for members (room = meeting id).
- Scheduler: in-process thread (single), half-hourly re-fetch per active Case File (skip during meetings and when GPU busy), reminders, digest at 08:00, cleanup of expired codes; every automatic action audited as "Vaidyx (automatic)".
- Notifications: in-app store + browser push (pywebpush, VAPID keys in data/, localhost), per-role rules (R06-Q14 for residents), no UHID in push text.
- Accounts: email login names, must_change_password, admin reset (core exception), profile fields, roles incl. resident (end date), auditor, outside expert (guest, meeting only), TOTP flag.
- Access: break-glass (Vaidyx admin: reason required, owner notified, audited); coordinator: date, agenda, archive with reason only; archive instead of delete; outside experts: consent view; chats never to supporting doctors; residents cannot sign; removed residents lose access.
- Protocols: cup.json (draft). Summary slot templates per protocol derived from records + required_facts.
- Published cases: search local library index first, then PubMed E-utilities / Europe PMC (diagnosis words only, logged), doctor picks.
- Security: rate limits (login, join code, ask), CSRF double-submit on state-changing routes for the new site, input validation (pydantic), size limits on uploads, path safety, no secrets in responses, security headers kept, audit on everything, TB idle timeout.

## 6. Demo PACS
Orthanc (existing install) with DICOMweb and OHIF. Images: TCIA CC BY collections only (plan in scratchpad pacs/tcia_plan.md, manifest at /data/vaidyx/tb_resources/dicom_public/MANIFEST.csv with collection, licence, DOI, series UID, date). Credit line in the OHIF/about page and in the HIMS radiology module footer. No model ever reads images.
