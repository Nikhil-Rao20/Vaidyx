## What looked solid (the reviewer's words, shortened)
The state guards: start only from planned; end refuses closed or cancelled; cancel refuses a running meeting. Next case resets the
opened record, the timer, presenting, spotlight and the live decision. The double-save guard holds apart from finding 1. Live events are
shaped per socket (waiting and non-admitted viewers get no private events; outside experts get no identity). A reconnect gets the full
state. Ending a meeting cancels the agent tasks. The scheduler's meeting jobs run on the app loop; `take_off_agendas` never touches a
running meeting. Coordinator-only routes check `session` or `board_record`; the frontend tears down sockets, LiveKit and timers on
unmount.
